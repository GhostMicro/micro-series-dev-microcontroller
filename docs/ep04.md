# ตอนที่ 4: ESP32: เชื่อมต่อโลกอินเทอร์เน็ต (ตอนที่ 2)

ในตอนที่แล้วเราได้เรียนรู้วิธีอ่านค่าจากเซนเซอร์ไปแล้ว แต่ค่าเหล่านั้นจะไม่มีประโยชน์เลยถ้าเราต้องเดินมาดูที่หน้าจอคอมพิวเตอร์ตลอดเวลา วันนี้เราจะทำให้ ESP32 "พูดคุย" กับเราผ่านอินเทอร์เน็ตครับ

## 1. การใช้ Blynk IoT: สร้าง Dashboard สวยๆ ใน 5 นาที

**Blynk** คือแพลตฟอร์มที่ช่วยให้เราสร้างแอปพลิเคชันบนมือถือเพื่อควบคุม ESP32 ได้โดยไม่ต้องเขียนโค้ด Mobile App เอง

* **หลักการทำงาน:** ESP32 จะเชื่อมต่อกับ Blynk Cloud ผ่าน Wi-Fi และแอปในมือถือเราก็จะดึงข้อมูลจาก Cloud มาแสดงผล
* **ขั้นตอน:**
  
  1. สมัครใช้งานที่ [blynk.io](https://blynk.io) และสร้าง Template เพื่อรับ **Auth Token**
  2. ติดตั้ง Library `Blynk` ใน Arduino IDE
  3. ใช้ Code ตัวอย่าง `BlynkSimpleEsp32` ใส่ชื่อ Wi-Fi, รหัสผ่าน และ Token

* **จุดเด่น:** มี Widget อย่างปุ่มกด (Button), กราฟ (Chart) และเกจวัด (Gauge) ให้เลือกใช้ฟรี

---

### 2. การแจ้งเตือนผ่าน LINE Notify: เมื่อเกิดเหตุด่วนให้บอกไลน์

นี่คือฟีเจอร์ที่คนไทยชอบที่สุด เช่น "น้ำล้นแล้ว!" หรือ "พบขโมยในบ้าน!" ESP32 สามารถส่งข้อความเข้ากลุ่ม LINE ของเราได้โดยตรง

* **วิธีการ:** เราต้องไปออกตั๋วที่เรียกว่า **Line Token** จาก [notify-bot.line.me](https://notify-bot.line.me/)
* **ตัวอย่างคำสั่ง (Conceptual):**

```cpp
LINE.notify("อุณหภูมิห้องสูงเกินไป: " + String(temp) + " องศา");

```

* **ข้อดี:** ไม่ต้องเปิดแอปค้างไว้ แจ้งเตือนเด้งขึ้นหน้าจอมือถือทันทีเหมือนมีเพื่อนทักมา

---

### 3. การสร้าง Web Server อย่างง่าย: ควบคุมผ่าน Browser

ถ้าเราไม่อยากพึ่งพา Cloud ข้างนอก เราสามารถสั่งให้ ESP32 ทำตัวเป็น **"เซิร์ฟเวอร์จิ๋ว"** ให้เราเอาคอมพิวเตอร์หรือมือถือเครื่องอื่นในบ้าน เข้ามาที่เลข IP ของบอร์ดเพื่อดูข้อมูลหรือกดเปิด-ปิดไฟได้

* **Libary ที่ใช้:** `WiFi.h` และ `WebServer.h`
* **การทำงาน:** บอร์ดจะ Generate หน้า HTML ออกมา เมื่อเรากดปุ่มบนหน้าเว็บ บอร์ดจะรับคำสั่งนั้นไปสั่งงานขา GPIO อีกที

#### วิธีนี้คือการทำให้ ESP32 กลายเป็น "เว็บไซต์ส่วนตัว"

* **หลักการ:** เมื่อเราเอา IP Address ของ ESP32 ไปกรอกใน Browser (Chrome/Safari) บอร์ดจะส่งหน้าเว็บ HTML ออกมาให้เรากดเปิด-ปิดไฟได้โดยตรง
* **จุดเด่น:** ไม่ต้องพึ่งพา Cloud ภายนอก ทำงานได้เร็วมากเมื่ออยู่ในวง Wi-Fi เดียวกัน

---

#### **ตัวอย่างโค้ด: การเชื่อมต่อ Wi-Fi และส่งค่าเบื้องต้น**

```cpp
#include <WiFi.h>

const char* ssid = "ชื่อไวไฟของคุณ";
const char* password = "รหัสผ่านไวไฟ";

void setup() {
  Serial.begin(115200);
  WiFi.begin(ssid, password); // เริ่มการเชื่อมต่อ

  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }

  Serial.println("");
  Serial.println("WiFi connected!");
  Serial.print("IP address: ");
  Serial.println(WiFi.localIP()); // แสดงเลข IP เพื่อใช้เข้า Web Server
}

void loop() {
  // ใส่โค้ดส่งข้อมูลขึ้น Cloud หรือเช็คสถานะที่นี่
}

```

### 4. สรุปความแตกต่าง: เลือกใช้แบบไหนดี?

| วิธีการ | ความยาก | ข้อดี | เหมาะกับงานแบบไหน |
| --- | --- | --- | --- |
| **Blynk** | ง่ายมาก | สวยงาม, มีกราฟ, คุมจากนอกบ้านได้ง่าย | Smart Home, โปรเจกต์ส่งอาจารย์ |
| **LINE Notify** | ง่าย | แจ้งเตือนทันใจ, ทุกคนมี LINE อยู่แล้ว | ระบบเตือนภัย, รายงานสถานะประจำวัน |
| **Web Server** | ปานกลาง | ทำงานในวงแลนได้แม้เน็ตตัด, ปรับแต่งหน้าเว็บได้เอง | ตู้คุมไฟในโรงงาน, งานที่เน้นความเป็นส่วนตัว |

---

### **⚠️ ข้อควรระวังด้านความปลอดภัย (Security First)**

* **API Token:** เปรียบเสมือนกุญแจบ้าน หากใครรู้ Token ของ Blynk หรือ LINE Notify ของคุณ เขาจะสามารถสั่งงานอุปกรณ์ของคุณได้ทันที
* **Hardcoding Credentials:** หลีกเลี่ยงการอัปโหลดโค้ดที่มีชื่อ Wi-Fi และรหัสผ่านลงใน GitHub หรือแชร์ให้ผู้อื่นดูโดยตรง
* **Update Firmware:** หากทำโปรเจกต์ใช้งานจริง ควรตรวจสอบ Library ให้เป็นเวอร์ชันล่าสุดเสมอเพื่อปิดช่องโหว่ความปลอดภัย

---

### 5. [!CAUTION] ข้อควรระวังเรื่องความปลอดภัย

เมื่อบอร์ดของคุณเชื่อมต่ออินเทอร์เน็ต มันจะมีความเสี่ยงทันที:

1. **Hardcode Token:** อย่าเผลอ Upload โค้ดที่มี Auth Token หรือรหัส Wi-Fi ลงใน GitHub สาธารณะ
2. **HTTPS/SSL:** การส่งข้อมูลบน ESP32 ส่วนใหญ่เป็นแบบไม่เข้ารหัส (HTTP) หากเป็นงานสำคัญควรศึกษาวิธีการใช้ SSL Fingerprint เพื่อความปลอดภัย
3. **API Token:** เปรียบเสมือนกุญแจบ้าน หากใครรู้ Token ของ Blynk หรือ LINE Notify ของคุณ เขาจะสามารถสั่งงานอุปกรณ์ของคุณได้ทันที
4. **Hardcoding Credentials:** หลีกเลี่ยงการอัปโหลดโค้ดที่มีชื่อ Wi-Fi และรหัสผ่านลงใน GitHub หรือแชร์ให้ผู้อื่นดูโดยตรง
5. **Update Firmware:** หากทำโปรเจกต์ใช้งานจริง ควรตรวจสอบ Library ให้เป็นเวอร์ชันล่าสุดเสมอเพื่อปิดช่องโหว่ความปลอดภัย
